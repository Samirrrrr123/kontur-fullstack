# Демонстрация проекта Контур

## Что сказать в начале

«Контур — платформа для публикации статей и новостей о цифровой культуре. Посетители читают материалы без регистрации. После входа можно публиковать свои статьи, оставлять комментарии и ставить лайки. За основу взят второй вариант задания — блог со статьями и комментариями».

## Сценарий показа на 5–7 минут

1. Открыть сайт без входа. Показать ленту и статью. Объяснить, что материалы загружаются с API, а не записаны в интерфейсе.
2. Выбрать тему «Дизайн», затем вид «Новости». Объяснить, что фильтры передаются серверу через параметры запроса. Вернуть «Все темы» и «Все публикации».
3. Нажать «Написать» без входа. Показать перенаправление на страницу входа.
4. Войти как samir@kontur.local с паролем Kontur2026!. Открыть «Мои публикации».
5. Создать короткую статью с названием, темой и текстом. Открыть её, изменить название через «Редактировать» и обновить страницу.
6. Выйти и войти как artem@kontur.local с тем же паролем. Найти созданную статью, поставить сердечко, убрать его и поставить снова. Написать комментарий.
7. Показать, что у читателя нет кнопки редактирования чужой статьи. При желании показать в Postman, что сервер тоже запрещает изменение и возвращает 403.
8. Вновь войти первым аккаунтом. Удалить только созданную для демонстрации статью через «Мои публикации» и подтвердить действие.
9. Показать структуру папок и кратко назвать технологии. Для Backend КТ отдельно показать `docker compose up --build` и запрос без токена с ответом 401.

Первые два аккаунта — обычные пользователи с одинаковыми возможностями. Второй аккаунт нужен, чтобы наглядно показать права владельца.

## Как объяснить базу данных

«База данных — постоянное хранилище проекта. Здесь четыре связанные таблицы: users — пользователи, posts — публикации, comments — комментарии, likes — реакции. В posts есть authorId, который указывает на автора. В комментарии сохраняются postId и authorId. В лайке сохраняются postId и userId. Одному пользователю разрешён один лайк на статью».

«Локально база находится в файле SQLite. В варианте запуска через Docker Compose используется PostgreSQL. С базой работает TypeORM: я описываю сущности, а ORM выполняет запросы для создания, чтения, изменения и удаления записей».

Показывайте тот режим, который реально запущен. Не называйте локальный файл SQLite базой PostgreSQL.

## Как объяснить связь частей проекта

«React показывает интерфейс. TypeScript проверяет типы данных. React Router переключает страницы. Zustand хранит состояние входа и списка публикаций. Axios отправляет запросы серверу. Сервер на Express проверяет данные и права, затем через TypeORM обращается к базе».

Пример: нажатие «Опубликовать» → Zustand → Axios POST /api/posts с JWT → Express проверяет токен и данные → TypeORM сохраняет статью → сервер возвращает статью → открывается её страница.

## Частые вопросы

**Что такое CRUD?** Создание, чтение, изменение и удаление данных. В проекте все четыре операции реализованы для публикаций.

**Что такое JWT?** Подписанный сервером токен, подтверждающий вход. После входа браузер хранит его и передаёт в заголовке Authorization: Bearer. Сервер проверяет подпись и срок действия.

**Где хранятся пароли?** В users.passwordHash хранится bcrypt-хеш. Исходный пароль в базу не записывается.

**Почему нельзя изменить чужую статью?** Сервер сравнивает идентификатор пользователя из JWT с authorId публикации. Если они разные, возвращает 403.

**Что значит 401 и 403?** 401 — нет действительного входа. 403 — вход есть, но нет права на конкретное действие.

**Что такое CORS?** Настройка сервера, разрешающая браузеру обращаться к API с явно указанных адресов фронтенда.

**Что сохраняется после закрытия сайта?** Публикации, аккаунты, комментарии и лайки остаются в базе. При выходе из аккаунта удаляется только токен входа из браузера.

**Нужна ли админка?** В задании блога управление публикациями доступно их авторам. Для этого есть кабинет «Мои публикации». Отдельной роли администратора в текущем проекте нет.

**Откуда новости?** Пользователи публикуют их вручную. Новость и статья — два вида публикации в одной таблице.

## Что открыть заранее

Сайт, папку проекта, этот сценарий. Для показа исходников удобен VS Code, но достаточно любого редактора. Презентация готовится отдельно. Перед парой проверьте вход обоими аккаунтами и создание одной статьи. Для локального показа после установки интернет не нужен.

## Дополнительные возможности для показа

«Популярные материалы выбираются по количеству лайков в базе. Сервер сортирует публикации и отдаёт первые три. При равенстве лайков выше более новая публикация. Это простой рейтинг, а не персональный алгоритм рекомендаций».

«Системная тема использует настройку оформления, которую сообщает браузер через prefers-color-scheme. JavaScript проверяет её методом matchMedia. Если устройство предпочитает тёмную тему, сайт включает тёмную; если светлую — светлую. Обработчик change обновляет оформление при изменении этой настройки».

Показ с двумя аккаунтами — удобный способ продемонстрировать общение: Самир публикует, Артём комментирует и ставит лайк. Затем Самир редактирует свою статью. В аккаунте Артёма кнопки редактирования статьи Самира нет, а сервер запрещает такое действие. Смена аккаунта нужна для этого сценария, а не для обычного использования сайта.

Презентация и показ интерфейса проходят в браузере после запуска Start.cmd. Для этого VS Code необязателен. Адрес localhost относится к компьютеру, где запущен сервер. Для показа на другом компьютере нужно перенести проект и подготовить запуск заранее.

# Контур

Fullstack-платформа для публикации статей и новостей о технологиях, дизайне, играх и интернете. Основа — вариант №2 «Блог-платформа со статьями и комментариями». Дополнительно реализованы фильтры по теме и виду публикации, лайки и кабинет автора.

## Запуск после скачивания из GitHub

1. Установите Node.js версии 22 или новее.
2. Скачайте репозиторий через Code → Download ZIP и распакуйте его.
3. Запустите `Install.cmd`. Для установки зависимостей нужен интернет.
4. Запустите `Start.cmd`. Он откроет http://127.0.0.1:3000.

Окно сервера оставьте открытым на время показа. Остановка — Ctrl+C. VS Code для запуска не нужен.

Альтернативно в терминале из папки проекта:

```sh
npm install
npm run build
npm start
```

## Повторный запуск на подготовленном компьютере

Если зависимости и сборка уже установлены, достаточно открыть `Start.cmd`. После подготовки можно показывать сайт без интернета: шрифты и стили включены в сборку.

Локальная база автоматически создаётся в `data/kontur.sqlite`. Это SQLite-база на сервере. Отдельная установка СУБД для этого режима не требуется. Пользователи и демонстрационные публикации добавляются при первом запуске пустой базы.

Не удаляйте `data`, если хотите сохранить свои публикации и аккаунты. Для резервной копии остановите сервер и скопируйте эту папку.

## Запуск по требованию Backend КТ через Docker Compose

Установите Docker Desktop с https://www.docker.com/products/docker-desktop/ и дождитесь запуска Docker Engine. В папке проекта выполните:

```sh
docker compose up --build
```

Приложение и PostgreSQL запускаются одной командой. Открывайте http://127.0.0.1:3000. База находится в Docker volume `kontur_db` и сохраняется после остановки контейнеров. Остановка:

```sh
docker compose down
```

Не запускайте локальный сервер и Docker-версию одновременно на порту 3000. Данные SQLite и PostgreSQL независимы: автоматический перенос между ними не реализован.

Docker-конфигурация подготовлена, но фактический запуск контейнеров на данном компьютере не проверялся: Docker Desktop отсутствует. Перед сдачей Backend КТ нужно запустить этот режим и проверить API из Postman.

## Переменные окружения

Необязательно скопируйте `.env.example` в `.env` для локальных настроек.

| Переменная | Назначение |
| --- | --- |
| VITE_API_URL | Адрес API для фронтенда; по умолчанию `/api` |
| PORT | Порт сервера; по умолчанию 3000 |
| HOST | Адрес привязки сервера; локально 127.0.0.1 |
| JWT_SECRET | Ключ подписи JWT; локально автоматически создаётся в `data/session-secret` |
| CORS_ORIGIN | Явный список разрешённых адресов фронтенда через запятую |
| DATABASE_URL | Подключение к PostgreSQL; без неё используется SQLite |
| DB_FILE | Путь к файлу локальной базы |
| SEED_DEMO | `false` отключает заполнение демонстрационными данными |

После изменения VITE_API_URL пересоберите фронтенд. В Docker адрес API тоже `/api`, поэтому браузер обращается к тому же адресу, что обслуживает сайт.

## Стек и структура

Frontend: React, TypeScript, Vite, React Router, Axios, Zustand, CSS, Lucide.
Backend: Node.js, Express, TypeORM, JWT, bcryptjs, Zod.
База: PostgreSQL в Docker-режиме, SQLite через sql.js для локального показа.

```text
src/App.tsx          страницы и компоненты интерфейса
src/store.ts         состояние входа, загрузка и CRUD публикаций через Zustand
src/api.ts           Axios-клиент и JWT-interceptors
src/types.ts         типы данных и темы
src/style.css        оформление и адаптивность
backend/app.js       API, валидация и права доступа
backend/database.js  ORM-модели и подключение к базе
backend/seed.js      стартовые публикации и аккаунты
backend/server.js    запуск сервера
postman/             коллекция запросов API
tests/              интеграционная проверка API
```

В браузере localStorage хранит JWT и выбранную тему оформления. Данные аккаунтов, публикаций, комментариев и лайков хранятся на сервере. Пароли хешируются bcrypt, JWT действует 12 часов. Изменение и удаление публикации разрешены только владельцу. Свой комментарий может удалить только его автор. Повторная отправка запроса на лайк не увеличивает счётчик.

## Разработка и проверки

В одном терминале запустите `npm start`, в другом `npm run dev`. Vite доступен на http://127.0.0.1:5173 и проксирует `/api` на сервер порта 3000.

```sh
npm run build
npm test
```

Тесты используют отдельную временную базу и не меняют ваши данные. Проверяются регистрация, вход, хеширование, публичное чтение, CRUD, права автора, фильтры, лайки, комментарии, CORS и сохранение данных после повторного подключения.

## Проверка API в Postman

Импортируйте `postman/Kontur.postman_collection.json`. Базовый адрес коллекции — `http://127.0.0.1:3000/api`. Выполните «Вход автора», затем «Создать статью»: token и postId сохранятся в переменных коллекции. Выполните «Вход читателя» для readerToken. Последующие запросы используют эти значения.

Запросы удаления запускайте на статье, созданной для проверки. Без токена защищённые маршруты возвращают 401; попытка изменить чужую публикацию возвращает 403; некорректные данные — 400.

КТ1: публичная лента с API, VITE_API_URL, JWT, Axios-interceptor, защищённые страницы `/mine`, `/write`, `/edit/:id` и перенаправление на вход.

Схема базы синхронизируется ORM при запуске для этого учебного проекта. Автоматический импорт внешних новостей, загрузка изображений, чаты и подписки не входят в текущую версию.

## Тема оформления

Кнопка с солнцем или луной в верхней панели открывает выбор светлой, тёмной или системной темы. Выбор сохраняется в браузере. Системная тема следует настройке операционной системы. Она не влияет на аккаунты и содержимое базы.

## Популярные публикации и демонстрационное наполнение

Раздел «Больше всего лайков» получает данные из `GET /api/posts/popular`. Сервер считает записи likes для каждой публикации, сортирует по убыванию и возвращает первые три. При одинаковом количестве лайков выше более свежая публикация. Подборка обновляется при открытии или обновлении ленты.

Стартовое наполнение включает дополнительные статьи, новости, шесть демонстрационных участников обсуждений, комментарии и лайки. Эти записи созданы для учебного показа; счётчики рассчитаны по базе, а не нарисованы в интерфейсе. Повторное заполнение не создаёт одинаковые лайки.

Системная тема определяется браузером через `window.matchMedia('(prefers-color-scheme: dark)')`. Если запрос совпал, применяется тёмная тема; иначе светлая. Событие change позволяет следовать изменению настройки устройства. Ручной выбор темы имеет приоритет.

## Свои публикации в общей ленте

Если authorId статьи совпадает с id вошедшего пользователя, в карточке показывается метка «Ваш пост» и ссылка «Изменить». Это работает в общей ленте, популярной подборке и большом блоке «В фокусе». У чужих публикаций этих действий нет. Удаление доступно из «Моих публикаций». Сервер отдельно проверяет владельца при изменении и удалении.

Авторы могут комментировать собственные публикации: это позволяет отвечать читателям и дополнять обсуждение. В стартовом наполнении есть публикации всех восьми демонстрационных участников.
